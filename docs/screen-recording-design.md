# 画面録画の設計書（Design Doc）

- **版**: 1.0（案。実装前）
- **日付**: 2026-11-21
- **対象**: 画面録画（F-021〜F-040）
- **関連**: [要件定義書](requirements.md)、[設計書（詳細）](design.md) の 23〜26 章、[機能一覧](features.json)、[ADR](adr/README.md)

この文書は、画面録画の全体像をまとめる。詳細な仕様（数値、表、手順）は [設計書](design.md) の 23〜26 章に書く。判断の理由は [ADR](adr/README.md)（ADR-0016〜0025）に書く。

---

## 1. 目的と範囲

### 目的

- 全画面（プライマリ画面）の操作を、10fps・H.264・mp4 の動画として記録する。
- 録画中に、アプリの窓（256×80）が映り込まない。
- 2 時間まで録画でき、途中で空き容量が足りなくなっても、システムの安定性を優先して止める。

### 範囲外（今は対象にしない）

- 画面の選択（将来対応。内部では画面 ID で扱う）。
- fps の変更の手段（コマンドライン、メニュー。将来対応。今は既定値 10）。
- macOS での対応（将来検討）。
- 音声だけの録音（MP3）。廃止した（[ADR-0017](adr/0017-drop-mp3-audio-only.md)）。
- 録画の復旧（異常終了や容量不足で止まった録画は、見られない。[ADR-0023](adr/0023-temp-files-cleanup.md)）。

## 2. 構成

```
┌──────────────────────── Electron ────────────────────────┐
│ メインプロセス（electron/main.cjs）                        │
│  - 窓（256×80。録画中は映像から除外）                       │
│  - 権限（media、display-capture）。ピッカーは出さない        │
│  - setDisplayMediaRequestHandler（プライマリ画面の ID）     │
│  - 一時ファイルの書き込み（3 分単位）                       │
│  - 空き容量の監視（10 秒ごと）                              │
│  - 多重化（停止時、.partial → .mp4）                       │
│  - 起動時の掃除（state.json を読む）                        │
│        ▲ preload（contextBridge。公開は録画用の API のみ）    │
│        ▼                                                    │
│ レンダラー（src/）                                          │
│  - 画面の取得（getDisplayMedia、10fps の時刻ごとに 1 枚）    │
│  - 縮小（1280×720）、同一フレームの判定                     │
│  - 符号化（VideoEncoder、H.264。HW 優先、なければ CPU）      │
│  - 音声の混合（マイク＋スピーカー、モノラル、Opus）           │
│  - 音量バーと dB 表示（混合した音声のレベル）                │
│  - 表示（経過時間、進み具合、エラー）                       │
└────────────────────────────────────────────────────────────┘
```

- 録画中の中間データは、レンダラーで符号化し、メインプロセスが一時ファイルに書く（[ADR-0024](adr/0024-save-from-main-process.md)）。
- 画面は `Blob` を作らない。mp4 も、メインプロセスがファイルへ直接書く。
- preload の公開範囲は、録画に必要な送信系 API に広げる（[ADR-0024](adr/0024-save-from-main-process.md)）。

## 3. 映像と音声の仕様

| 項目 | 値 | 根拠 |
|---|---|---|
| コンテナ | mp4 | 要件 F-024 |
| 映像 | H.264（`avc1`）、1280×720、10fps（CFR） | [ADR-0016](adr/0016-screen-video-format.md) |
| 映像のビットレート | 約 1Mbps（可変、目標値） | ADR-0016 |
| 縦横比 | 保ち、余白は黒 | ADR-0016 |
| 音声 | Opus、48kHz、モノラル、128kbps | ADR-0017 |
| 音声の混合 | マイク＋スピーカーのライン入力（`GainNode` で混ぜる） | F-022 |
| 録画時間 | 2 時間で自動停止 | F-029 |

- 映像と音声の時刻は、録画開始を 0 とし、一時停止の時間を除いて詰める（F-026）。
- 映像の時刻は、10fps の番号（フレーム番号 ÷ 10 秒）で決める。

## 4. 処理の流れ

### 4.1 録画中

1. 10fps の時刻（100ms ごと）に、画面の最新フレームを 1 枚選ぶ（撮影が間に合わなければ落とす）。
2. 1280×720 に縮小する。
3. 直前に処理したフレームと画素単位で比べる。同じなら、符号化も保存もしない（[ADR-0020](adr/0020-skip-identical-frames.md)）。
4. 違えば、H.264 に符号化する。ハードウェアを優先し、使えないときは CPU で符号化する（[ADR-0019](adr/0019-encoder-hw-first.md)）。
5. 符号化したサンプルを、メインプロセスへ送る。メインプロセスは、3 分ごとの一時ファイルに書く（[ADR-0018](adr/0018-intermediate-h264-segments.md)）。
6. 10 秒ごとに、空き容量を確認する。足りなくなったら止める（[ADR-0022](adr/0022-disk-space-stability.md)）。

### 4.2 停止時

1. 停止したら、`state.json` を `stopping` にし、`partialPath` を書く。
2. 空き容量を確認し、足りるときだけ mp4 を作る（`.partial` に書き、完了したら `.mp4` に変える）。
3. 一時ファイルのサンプルを順に読み、mp4 に多重化する（再符号化はしない）。同一フレームの時刻には、スキップフレームを置く（[ADR-0020](adr/0020-skip-identical-frames.md)）。
4. 進み具合を、約 0.5 秒ごとに画面へ送る（F-038）。
5. 成功したら、`.mp4` を Downloads に保存し、一時フォルダを削除する。`state.json` を `saved` にする。
6. 失敗したら、`.partial` を削除する。中間ファイルは残す（[ADR-0023](adr/0023-temp-files-cleanup.md)）。

## 5. 状態

| 状態 | 意味 | 次の状態 |
|---|---|---|
| `idle` | 待機 | `recording`（開始） |
| `recording` | 録画中 | `paused`（一時停止）、`stopping`（停止）、`stopped-space`（空き容量不足） |
| `paused` | 一時停止中（映像と音声を記録しない） | `recording`（再開）、`stopping`（停止） |
| `stopping` | 停止して mp4 を作っている | `saved`（成功）、`failed`（失敗。途中の mp4 を削除） |
| `failed` | mp4 の作成が途中で失敗した | `idle`（次回起動時に掃除） |
| `stopped-space` | 空き容量不足で止めた。mp4 は作らない | `idle`（次回起動時に掃除） |

- 一時停止中は、ボタンの表示を ▶ にする（F-002）。
- `stopping` と `stopped-space` の録画は、見られない（[ADR-0022](adr/0022-disk-space-stability.md)）。

## 6. 一時ファイルと状態ファイル

```
userData/
  recording-<開始時刻>/
    state.json          状態（recording / stopping / stopped-space / failed / saved）と partialPath
    seg-0001.bin        3 分（1800 フレーム）ごとのサンプル
    seg-0002.bin
    ...
Downloads/
  screen_<開始時刻>.mp4.partial   多重化中（完了したら .mp4 に変える）
  screen_<開始時刻>.mp4           完成
```

- `seg-*.bin` は、時刻・種類（映像、音声、スキップ）・長さを付けたサンプルを順に並べたコンテナ。
- 先頭がキーフレームになるとは限らない（繰り返しフレームの省略のため）。多重化は先頭から順に読むので、再生の開始点は問題にならない。
- `state.json` は、状態が変わるたびに書き換える。一時ファイルに書いてから置き換える。

## 7. 空き容量の判定

見積もり（720p、10fps、2 時間、1Mbps、仮）:

| 項目 | 値 |
|---|---|
| 中間データ | 約 1.0GB（1 時間あたり約 0.5GB） |
| mp4 | 約 1.0GB |
| 停止時のピーク | 約 2.0GB |

| 判定 | 条件（仮の値） | 動作 |
|---|---|---|
| 録画の開始前 | 空き ≥ 3GB | 足りなければ録画を始めない（F-035） |
| 録画中（10 秒ごと） | 空き < 中間データ＋0.5GB | 録画を止める。mp4 は作らない（決定） |
| 停止時（通常） | 空き ≥ 中間データ＋0.2GB | 足りれば mp4 を作る。足りなければ作らない |

## 8. 異常系と掃除

| 事象 | 動作 | 根拠 |
|---|---|---|
| 録画中の空き容量不足 | 録画を止める。mp4 は作らない。場所を表示し、`stopped-space` にする | F-035、F-039、ADR-0022 |
| 多重化の途中で失敗（容量不足、書き込みエラー） | `.partial` を削除。中間ファイルは残す | F-031、ADR-0023 |
| 権限の拒否 | F-033 のメッセージを表示。録画を始めない | F-033、ADR-0025 |
| 録画中のクラッシュ、電源断 | 次回起動時に中間ファイルと `.partial` を削除（見られない） | F-040、ADR-0023 |
| 停止中のクラッシュ | 次回起動時に中間ファイルと `partialPath` の `.partial` を削除 | F-040、ADR-0023 |
| `state.json` が読めない | 削除しない。ログに残す | ADR-0023 |
| 符号化が遅れる（CPU 上限） | フレームレートを下げる（停止時の多重化は対象外） | F-023、7.3a、ADR-0019 |

- 掃除は起動後に非同期で行う。失敗してもアプリは起動する。

## 9. 性能の目標

| 項目 | 目標 | 根拠 |
|---|---|---|
| 録画中の CPU 使用率 | 10% 以下。超えそうならフレームレートを下げる | 7.3a |
| 録画中のメモリ | 符号化の出力と待ち行列の一部だけ（3 分分をまとめて残さない） | F-030 |
| 停止時のメモリ | 多重化は 1 チャンクずつ書く（全体を溜めない） | 24.3 章 |
| 停止時の時間 | 多重化だけなので短い（実測で確認） | ADR-0018 |

## 10. 権限と安全性

- 権限は `media` と `display-capture` だけを許可する（7.2 章）。それ以外は拒否する。
- preload は、録画に必要な API だけを公開する。`ipcRenderer` は公開しない（[ADR-0024](adr/0024-save-from-main-process.md)）。
- 外部の URL は読み込まない。`dist/index.html` だけを読む。
- 画面の内容は外部に送らない。録画は、ローカルの一時フォルダと Downloads にだけ書く。

## 11. テスト方針

| 種類 | 対象 | 方法 |
|---|---|---|
| 静的検査（pytest） | 権限、preload の公開範囲、窓の寸法、MP3 の不在（録画の経路） | `tests/` に追加する（実装時） |
| 単体テスト（JavaScript、未導入） | コンテナの書き込み・読み込み、スキップフレームの判定、状態の遷移、掃除 | vitest の導入を検討する |
| E2E（Electron） | 録画の開始、一時停止、停止、保存、進み具合 | フェイク画面とフェイクマイクで操作する（設計書 20 章） |
| 成果物の検査（ffprobe） | フレームレート 10、H.264、1280×720、長さ一致、音声トラック、再生 | F-021〜F-027 の受け入れ条件 |
| 負荷の検査 | 録画中の CPU 使用率、停止時の時間 | 計測して記録する（F-036、7.3a） |
| 空き容量の検査 | 3 つの判定、停止の動作 | 仮想のディスク（容量を変えられる環境）で確認する |

- 受け入れ条件は、`docs/features.json` の各機能に書く。テストが通ったら `verification` を更新する。

## 13. 実装の順番（案）

1. 画面の取得と 10fps の時刻管理（レンダラー）。窓の除外（メインプロセス）。
2. 同一フレームの判定と、符号化（HW の判定を含む）。
3. 一時ファイルのコンテナ（書き込み、読み込み）。`state.json`。
4. 空き容量の監視と停止。
5. 多重化、`.partial`、保存の進み具合。
6. 起動時の掃除。
7. MP3 の録音の削除（ADR-0017）。
8. テストと検証（11 章）。

# 音声レコーダー（js-recorder）要件定義書

- **版**: 1.1（画面録画の要件を追加。実装は未着手）
- **日付**: 2026-11-21
- **対応する実装**: `master` の `37a128b` 以降（ワーキングツリーの内容）
- **機械可読の一覧**: [features.json](features.json)（機能 ID と検証状況）
- **設計**: [design.md](design.md)

この文書の数値と文言は、実装（`src/`、`electron/`）と一致させています。どちらかを変えたら、もう一方も変えてください。機能 ID は `features.json` と一致している必要があります（テストで検査します）。

---

## 1. 目的

マイクの音声を MP3 ファイルに録音する、小さなデスクトップ用アプリを作る。

- 操作は「開始」「一時停止」「再開」「停止」だけにする。
- 停止すると、MP3 を Downloads フォルダへ自動で保存する。保存先のダイアログは出さない。
- サーバーを使わず、すべての処理をアプリ内で行う。
- 追加: 同じ操作で、プライマリ画面の映像と音声（マイクとスピーカー）を mp4 ファイルに録画する（F-021〜F-040）。

## 2. 利用者と利用シーン

- **利用者**: 音声メモを手早く録音したい個人。
- **利用シーン**: 手元の PC で、マイクに向かって話す内容を録る。録音した MP3 は、あとで別のアプリで再生・共有する。

## 3. 用語

| 用語 | 意味 |
|---|---|
| 録音中 | 「開始」後、「一時停止」または「停止」の前の状態 |
| 一時停止中 | 「一時停止」後、「再開」または「停止」の前の状態 |
| 待機中 | 録音を開始していない状態（「停止」後を含む） |
| 経過時間 | 一時停止の時間を除いた、録音した長さ |
| 音量 | 直近約 50ms の音の大きさ（RMS）を dB で表した値 |

## 4. スコープ

### 4.1 対象

- Electron 45 のデスクトップアプリ（配布物は作らない。開発環境で起動して使う）。検証は Linux でのみ行った。
- 録音、一時停止、再開、停止、MP3 保存
- マイクの選択、音量表示、経過時間表示
- エラーの表示と、保存完了の表示
- 画面録画（プライマリ画面、10fps、H.264 の mp4、音声はマイクとスピーカー。F-021〜F-040）
- 対象の OS は Linux と Windows（画面録画の要件。macOS は将来検討）

### 4.2 対象外

- 音声の再生
- 保存先を選ぶダイアログ
- MP3 以外の音声形式、mp4 以外の映像形式
- 画面の選択（将来対応。今はプライマリ画面を固定で対象にする）
- fps の変更手段（コマンドラインやメニュー。将来対応。今は既定値 10 を使う）
- インストーラーなどのパッケージ化
- macOS での対応（将来検討）。Windows の動作確認は、実装後に行う（[10 章](#10-未決事項既知の課題)）
- エコーキャンセル・ノイズ抑制・自動音量調整（利用者に必要な場合は、後から追加する）

## 5. 機能要件

各機能の受け入れ条件は、ここに書いた数値と文言で判定します。機能の状態は `features.json` の `status`、`implemented`、`verification` で管理します。

### F-001 録音を開始する（must）

- **開始**ボタンを押すと、選択中のマイクから録音を始める。
- 録音中は経過時間が進む。
- 録音中は**開始**ボタンが無効になり、**一時停止**と**停止**が有効になる。
- 開始処理の途中で、もう一度開始を押しても録音を二重に始めない（F-017 を参照）。

### F-002 一時停止する（must）

- 録音中に**一時停止**を押すと、録音を止める。
- 一時停止中は経過時間が進まない。
- 一時停止中は音量バーが 0%、dB 表示が `-60.0 dB` になる。
- ボタンの表示が **▶**（再開）に変わる。

### F-003 再開する（must）

- 一時停止中に**再開**を押すと、同じファイルに続けて録音する。
- 再開すると経過時間が、一時停止の前の値から続けて進む。
- 1 つの MP3 ファイルに続けて書き込まれる。

### F-004 停止して MP3 を保存する（must。廃止: F-021、F-031 に置き換え）

- **停止**を押すと録音を終え、ボタンが待機中の状態に戻る。
- MP3 が Downloads フォルダに、ファイル名（F-006）で保存される。
- 保存先のダイアログは出ない。
- MP3 の長さが、一時停止を除いた録音時間と一致する。

### F-005 MP3 にエンコードする（must。廃止: F-024 に置き換え）

- 録音データをブラウザ内で MP3 に変換する。サーバーは使わない。
- 出力は **モノラル、44.1kHz、128kbps** の MP3 にする。
- 出力は `ffprobe` で有効な MP3 と判定される。

### F-006 ファイル名に録音開始時刻を付ける（must。廃止: F-032 に置き換え）

- ファイル名は `recording_YYYYMMDD_HHMMSS.mp3` の形式にする。時刻は**開始時**のローカル時刻を使う。
- 例: `recording_20261119_143025.mp3`
- 一時停止と再開をしても、ファイル名は変わらない。

### F-007 経過時間を 100ms 単位で表示する（must）

- 形式は `h:mm:ss.t`。`h` は時（常に表示）、`mm` と `ss` は 2 桁、`t` は 100ms の 1 桁（切り捨て）。
- 例: `0:00:00.0`、`0:01:02.7`
- 表示は約 30ms ごとに更新される。
- 一時停止中は値が変わらない。

### F-008 音量をバーと dB で表示する（must）

- 録音中・録画中の音量を、0〜100% のバーと dB の数値で表示する。録画中は、マイクとスピーカーを混ぜた音声のレベルを示す（決定）。
- dB の範囲は **-60.0 から 0.0**。表示は小数点以下 1 桁（例: `-17.6 dB`）。
- バーの割合は `(dB + 60) / 60 × 100` を 0〜100 に収めた値。
- 約 50ms ごとに更新される。
- バーの色は灰色 1 色。

### F-009 一時停止中は音量を 0 にする（must）

- 一時停止に入ると、音量バーが 0%、dB が `-60.0 dB` に戻る。

### F-010 マイクを選択する（must）

- 利用できる音声入力デバイスを、画面のプルダウンに一覧表示する。
- 録音中と一時停止中は、選択を変えられない。
- マイクの接続・切断に合わせて一覧を更新する（`devicechange` イベント）。

### F-011 起動時にマイク許可を求める（should）

- 起動時に一度マイクを要求し、デバイス名（ラベル）を表示できるようにする。
- 許可されないと、デバイス名は表示されない。

### F-012 エラーを画面に表示する（must）

エラー名ごとに、次のメッセージを画面下に 1 行で表示する。

| エラー名 | 表示するメッセージ |
|---|---|
| `NotAllowedError`、`SecurityError` | マイクの使用が許可されていません。OSやアプリのマイク設定を確認してください。 |
| `NotFoundError`、`OverconstrainedError` | マイクが見つかりません。マイクを接続してから再度お試しください。 |
| `NotReadableError`、`AbortError` | マイクを使用できません。他のアプリがマイクを使用していないか確認してください。 |
| その他 | エラーが発生しました: <メッセージ> |

- 入りきらない部分は末尾を `…` で省略する。全文は `title` 属性（マウスオーバー）で確認できる。
- デバイスが 1 つもないときは「マイクが見つかりません。マイクを接続してください。」と表示する。

### F-013 保存完了を画面に表示する（should）

- 停止後、保存中は「保存しています…」と表示する。進み具合（F-038）を表示するときは「保存しています… NN%」とする。
- 保存が完了したら「保存しました: <絶対パス>」に変える。例: `保存しました: /home/<ユーザー>/Downloads/recording_20261121_083000.mp3`
- 絶対パスが画面の幅に収まらないときは、横に流す（ティッカー表示。[設計書 16 章](design.md#16-ティッカー表示)）。
- 収まるときは流さずに表示する。
- メッセージ（ティッカーを含む）は、保存後に表示する。録音中と一時停止中は、メッセージを表示しない（エラーを除く）。
- Electron 以外（ブラウザでの表示）では、保存中の表示を出さず、「<ファイル名> を保存しました」と表示する。

### F-014 操作ボタンをアイコンで表示する（must）

- 開始は **●**、一時停止は **❚❚**、再開は **▶**、停止は **■**、ミュートは **マイクのアイコン**（ミュート中は斜線）。
- 各ボタンは 30×20px。
- 各ボタンに `aria-label` と `title` を付ける（開始、一時停止／再開、停止、ミュート）。

### F-015 動作状態のラベルを表示しない（must）

- 「待機中」「録音中」「一時停止中」の文字は表示しない。
- 状態はボタンの有効・無効と、経過時間の動きで示す。

### F-041 マイクをミュートする（should）

- 録音中と一時停止中に、ミュートボタンでマイクの音を止める。
- ミュート中は無音として記録し、時間軸は保つ。スピーカーの音は変えない。
- 録音を始めるたびに、ミュートは解除された状態で始まる（Issue #3）。

### F-016 ウィンドウを固定サイズにする（must）

- ウィンドウの内容の領域は **292×80px**（ミュートボタンを加えた 4 個のボタンに合わせて 256px から広げた）。
- リサイズ、最大化、全画面化はできない。
- すべての操作要素が収まり、スクロールは発生しない。

### F-017 開始ボタンの連打を防ぐ（should）

- 開始処理の途中、または録音中に、もう一度開始を押しても無視する。録音は二重に始まらない。

### F-018 日本語で表示する（should）

- 画面の文言（ボタンの `aria-label`、メッセージ、マイク名の既定表示）は日本語にする。
- `index.html` の `lang` は `ja`、`title` は「Video Recoder」。ウィンドウのタイトルも「Video Recoder」。

### F-019 停止処理の失敗に対応する（should、未実装）

- 停止処理（MP3 の完成、保存）が失敗しても、画面が録音中のまま止まらないようにする。
- エラーを画面に表示する。マイクと音声処理を解放する。次の録音を開始できる状態に戻す。
- 受け入れ条件（`features.json` の F-019）: 失敗時にエラーを表示する、ボタンが初期状態に戻る、マイクと `AudioContext` を解放する、次の録音を開始できる。

### F-020 一時停止・再開ボタンの連打を防ぐ（should、未実装）

- 一時停止・再開の処理の途中で、同じボタンを押されても二重に処理しない。
- 受け入れ条件（`features.json` の F-020）: 処理中の操作を無視する、状態が食い違わない、処理後にボタンが次の操作を受け付ける。

### 画面録画（F-021〜F-040）

画面録画は、既存の操作ボタン（開始、一時停止、再開、停止）をそのまま使う。録画の出力は、映像の mp4（F-032）だけになる。MP3 は出力しない。

### F-021 画面を録画する（must）

- **開始**を押すと、映像と音声の録画を始める。
- **一時停止**、**再開**、**停止**は、映像と音声の両方に効く（F-002、F-003、F-004）。
- 停止すると、映像の mp4 を Downloads フォルダに保存する（F-031、F-032）。MP3 は出力しない。
- 録画中は経過時間（F-007）で録画中であることを示す。録画中の専用の表示は出さない。
- 受け入れ条件（`features.json` の F-021）: 開始で映像と音声の録画が始まる、停止で mp4 が保存される。

> 決定（2026-11-21）: 録画の出力は mp4 だけ。MP3 は出力しない（10 章）。

### F-022 映像に音声を含める（must）

- 映像の mp4 には、次の 2 つの音声を含める。
  - マイク入力（選択中のマイク、F-010）
  - スピーカーのライン入力（システムの出力音）
- 2 つの音声は、モノラル 1 つのトラックにまとめる。音声の形式は Opus、48kHz、128kbps。
- 受け入れ条件（`features.json` の F-022）: mp4 に音声トラックがあり、マイクの音とスピーカーの音の両方が含まれる。

### F-023 映像を 10fps の CFR にする（must）

- 映像のフレームレートは **10fps の固定（CFR）** にする。
- 撮影が間に合わないフレームは落とす。フレームの複製や補間はしない。
- 受け入れ条件（`features.json` の F-023）: `ffprobe` でフレームレートが 10fps と判定される。

### F-024 映像の形式を H.264 の mp4 にする（must）

- コーデックは **H.264**。コンテナは **mp4**。
- 解像度は **1920 × 1080 px** にする。画面の縦横比が 16:9 でないときは、縦横比を保って収め、余白は黒にする。
- ビットレートは **約 3Mbps**（可変。目標値）。
- 符号化は録画中に行う（F-036）。停止時に再符号化しない（F-031）。
- 受け入れ条件（`features.json` の F-024）: `ffprobe` でコーデックが H.264、解像度が 1920×1080、ビットレートが約 3Mbps（目標値） である。

### F-025 マウスカーソルを映像に含めない（must）

- 映像には、マウスカーソルを含めない。
- 受け入れ条件（`features.json` の F-025）: 録画した映像にカーソルが映らない（確認は E2E の手順で行う）。

### F-026 一時停止中の映像と音声を記録しない（must）

- 一時停止の間は、映像と音声を記録しない。
- 再開すると、停止していた時間を除いて続けて記録する。映像の時刻は、詰めて続ける。
- 経過時間（F-007）と映像の長さが一致する。
- 受け入れ条件（`features.json` の F-026）: 一時停止を挟んだ録画の mp4 の長さが、停止時間を除いた経過時間と一致する。

### F-027 録画ウィンドウを映像から除外する（must）

- 録画中、アプリ自身の窓（292×80）は映像に映らない。
- 受け入れ条件（`features.json` の F-027）: 録画した映像に、アプリの窓が映らない。

### F-028 プライマリ画面を録画する（must）

- 録画の対象は、**プライマリ画面（全画面）** の 1 つだけにする。
- 画面は内部では**画面 ID**で扱う。将来の画面選択（4.2）に備えるため。今は、プライマリ画面の ID を固定値で指定する。
- 受け入れ条件（`features.json` の F-028）: 録画の対象が、プライマリ画面の ID で指定されている。

### F-029 録画時間の上限を 2 時間にする（must）

- 録画時間の上限は **2 時間**。
- 2 時間に達したら、録画を自動で止め、ここまでの映像と音声を保存する。保存完了の表示（F-013）と、上限に達したことを示すメッセージを表示する。
- 受け入れ条件（`features.json` の F-029）: 2 時間で録画が止まり、mp4 が保存される。

### F-030 3 分単位で一時ファイルに書き出す（must）

- 録画中に符号化した映像（H.264）と音声（Opus）は、**3 分ごと**に一時ファイルへ書き出す。
- 一時ファイルには、時刻つきの符号化データを順に並べる。1 フレームごとのファイルは作らない。
- メモリには、符号化の出力と待ち行列の一部だけを置く。3 分分をまとめて残さない。
- 一時ファイルは、停止して保存が完了するまで残す。保存が完了したら削除する。
- 受け入れ条件（`features.json` の F-030）: 録画中、メモリ上の映像データが 3 分分を超えない。3 分ごとに一時ファイルが切り替わる。保存完了後に一時ファイルが削除される。

### F-031 停止時に mp4 を作る（must）

- 停止時は、一時ファイルの符号化データを **mp4 に多重化する**。H.264 の再符号化はしない。
- 同一フレームの時刻には、直前のフレームを参照するスキップフレームを置く（F-037）。
- 作った mp4 を Downloads フォルダに保存する（保存先のダイアログは出さない）。
- 録画が見られるのは、mp4 の作成（多重化）が成功したときだけ（決定）。
- 書き込み中の mp4 は `screen_<時刻>.mp4.partial` の名前にし、完了したら `.mp4` に変える。
- 多重化が途中で失敗したとき（空き容量の不足、書き込みエラーなど）は、途中の mp4（`.partial`）を削除する（決定）。中間ファイルは残す（次回起動時の掃除で消える）。
- 受け入れ条件（`features.json` の F-031）: 停止後に mp4 が Downloads に保存される。映像の符号化は録画中に行われ、停止時に再符号化しない。保存後に一時ファイルが削除される。

### F-032 映像のファイル名を付ける（must）

- 映像のファイル名は `screen_YYYYMMDD_HHMMSS.mp4` の形式にする。時刻は**録画開始時**のローカル時刻を使う。
- 例: `screen_20261119_143025.mp4`
- 一時停止と再開をしても、ファイル名は変わらない。
- 既存の MP3 のファイル名（F-006）とは接頭辞で区別する。

### F-033 画面収録の権限を求め、拒否時にエラーを表示する（must）

- 画面を録画するため、OS と アプリの**画面収録の権限**を要求する（[設計書 25 章](design.md#25-画面収録の権限)）。
- 権限が拒否されたときは、F-012 の表の形式に倣って、次のメッセージを表示する。
  - 「画面の録画が許可されていません。OSやアプリの画面収録の設定を確認してください。」
- 受け入れ条件（`features.json` の F-033）: 権限が拒否されると、そのメッセージが表示され、録画は始まらない。録画も始めない。

### F-034 フレームレートを設定値にする（should）

- フレームレートは、設定値として 1〜30fps で指定できるようにする。既定値は **10fps**。
- 今回の実装では既定値だけを使う。変更の手段（コマンドライン、メニュー）は将来の対応とする（4.2）。
- 受け入れ条件（`features.json` の F-034）: 既定値が 10 である。1〜30 の範囲外の値は使われない（既定値に戻す）。

### F-035 空き容量を確認する（must）

- 録画を始める前に、中間ファイルを置く場所の空き容量を確認する。空き容量が **6GB 未満**なら、録画を始めない（仮。2 時間分の中間データ約 2.6GB と mp4 約 2.6GB に余裕を足した値。ADR-0027）。
- 録画中は **10 秒ごと**に確認する。空き容量が「現在の中間データの大きさ ＋ 0.5GB」を下回ったら、録画を止め、中間ファイルを残す（仮）。
- 録画を止めたときは、「空き容量が不足したため録画を止めました」を画面に表示し、中間ファイルの場所を示す。
- 空き容量の不足で止めるときは、システムの安定性を優先する。mp4 は作らず、ディスクへの追加の書き込みを行わない（決定）。
- 通常の停止後、空き容量が「中間データの大きさ ＋ 0.2GB」以上あるときだけ mp4 を作る（仮）。足りないときは mp4 を作らず、中間ファイルを残す（この録画は見られない。決定）。
- 受け入れ条件（`features.json` の F-035）: 空き容量が足りないと録画が始まらない。録画中に不足したら、mp4 を作らずに録画を止め、中間ファイルを残す。通常の停止で容量が足りないときも、mp4 を作らず中間ファイルを残す。

### F-036 符号化をハードウェアで行い、使えないときは CPU で行う（must）

- 映像の H.264 の符号化は、ハードウェア符号化が使えるときはそれを使う。
- ハードウェア符号化が使えないときは、CPU（ソフトウェア符号化）で録画中に符号化する。この場合は CPU 使用率の上限（7.3a）が効く。上限を超えそうなときは、フレームレートを下げる。
- 使った方式（ハードウェアかソフトウェアか）を、録画ごとに記録する。
- 受け入れ条件（`features.json` の F-036）: ハードウェア符号化が使えない環境でも録画が完了する。使った方式が記録される。録画中の CPU 使用率が 10% 以下（上限を超えそうなときはフレームレートが下がる）。

### F-037 同じ画面のフレームは保存しない（must）

- 直前のフレームと同じ画面（縮小後、画素単位で一致）のフレームは、最初の 1 フレームだけ符号化してスキップフレームとして一時ファイルに保存する。以降の同じフレームは符号化も保存もせず、停止時の多重化で同じスキップフレームを置く。
- 停止時の mp4 では、その時刻に直前のフレームを参照するスキップフレームを置き、映像は 10fps の CFR を保つ（F-023）。
- 受け入れ条件（`features.json` の F-037）: 同じフレームは、最初の 1 フレームだけがスキップフレームとして一時ファイルに保存され、以降は保存されない。mp4 は ffprobe で 10fps と判定される。一時停止と再開をはさんでも、映像が正しく再生される。

### F-038 停止時の進み具合を表示する（must）

- 停止してから mp4 を作るまでの間、進み具合を割合（%）で表示する。表示は「保存しています… NN%」の形式にする（F-013 の拡張）。
- 割合は、多重化したサンプルの量（時間）を、録画全体の量で割って求める。
- 表示は約 0.5 秒ごとに更新する。終わったら「保存しました: <絶対パス>」に変わる（F-013）。
- 受け入れ条件（`features.json` の F-038）: 停止中に割合が増えていく。終わると保存完了の表示に変わる。

### F-039 空き容量の不足で止めた録画の場所を案内し、次回起動時に掃除する（must）

- 空き容量が足りなくなって録画を止めたときは、中間ファイルの場所（絶対パス）を画面に表示する（F-035）。
- 次回起動時に、前回の一時ファイルを削除する（決定）。
- 注意: 空き容量の不足で止めた録画は、mp4 にならない。次回起動時の掃除で中間ファイルが消えるため、この録画は見られない（決定。システムの安定性を優先する）。
- 受け入れ条件（`features.json` の F-039）: 録画を止めたときに場所が表示される。次回起動時に、前回の一時ファイルが削除される。

### F-040 異常終了のときは中間ファイルを自動で削除する（must）

- 録画中に、アプリが正常に終了しなかった（クラッシュ、電源断など）ときは、次回起動時に中間ファイルを自動で削除する（決定）。
- 正常な停止と保存が終わったときは、一時ファイルを削除する（F-030）。
- 注意: 異常終了の録画は、mp4 にならない。中間ファイルは次回起動時に削除されるため、この録画は見られない（決定）。
- 異常終了で途中まで書いた mp4（`.partial`）も、次回起動時に削除する（決定）。
- 受け入れ条件（`features.json` の F-040）: 録画中に強制終了し、次回起動すると中間ファイルが削除される。

## 7. 非機能要件

### 7.1 性能

- 経過時間の表示は約 30ms ごと（F-007）。
- 音量の表示は約 50ms ごと（F-008）。
- 音声は 128 サンプルずつ受け取り、MP3 の 1152 サンプル単位のブロックにまとめてエンコードする（設計書 4、5 章）。

### 7.2 セキュリティ

- `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。
- 権限は `media`（マイク）と、画面収録（`display-capture` と、画面の取得に必要な `media`）だけを許可する。それ以外の権限は拒否する（F-033、[設計書 25 章](design.md#25-画面収録の権限)）。
- 外部の URL は読み込まない。`dist/index.html` だけを読み込む。
- 画面からメインプロセスへの送信は行わない。preload が公開する API は `window.recorder.onSaved` だけ（設計書 12 章）。

### 7.3 互換性

- Electron 45.4.1、React 19.3.1、Vite 8.3.8、lamejs 1.2.1。
- Node.js は **22.12 以上**（Electron 45 と依存パッケージの要件）。
- 検証環境は Linux（arm64）。Node.js 20.19.2 でもビルドとテストは成功したが、起動は Node 22.12 以上を前提とする。
- 画面録画の対象 OS は **Linux と Windows**。macOS は将来検討する（4.2）。Windows での確認は実装後に行う（10 章）。

### 7.3a 画面録画の性能

- 録画中の CPU 使用率は **10% 以下**にする。
- この上限は録画中に適用する。ハードウェア符号化が使えないときは CPU で符号化するため、この上限が効く（F-036）。停止時の多重化（再符号化なし）には当てはめない。
- CPU 使用率の上限を優先する。上限を超えそうなときは、フレームレートを 10fps より下げてよい（F-023 の例外）。映像の内容より、CPU の上限を守ることを優先する。
- 受け入れ条件: 録画中の CPU 使用率を計測し、10% 以下であることを確認する（[9.2 章](#92-electron-での確認e2e)）。

### 7.4 アクセシビリティ

- 各操作ボタンに `aria-label` を付ける。
- 音量バーは `role="meter"` と `aria-valuemin`、`aria-valuemax`、`aria-valuenow` を持つ。
- 動きを減らす設定（`prefers-reduced-motion`）では、ティッカーを流さない。

### 7.5 可用性と保存

- ネットワークを使わない。オフラインで動く。
- 保存先は Downloads に固定する。同名のファイルは上書きされる（F-006、設計書 17 章）。

## 8. 制約・前提

- マイクの使用には OS とアプリの許可が必要。
- ファイル名は秒単位のため、同じ秒に録音を開始すると、同じ名前になって上書きされる。
- 画面録画の一時ファイル（H.264）と mp4 は、2 時間でそれぞれ約 1GB になる。空き容量の確認は F-035 で行う。
- 画面録画の時間の上限は 2 時間（F-029）。映像は H.264 で符号化し、3 分ごとに一時ファイルへ書き出す（F-030）。
- 配布用の署名、インストーラー、macOS のマイク使用説明（`NSMicrophoneUsageDescription`）は未対応。

### 画面録画の未決事項（実装前に確認する）

- **H.264 の符号化（F-024、F-036）**: Electron 45 で `VideoEncoder` が H.264（`avc1`）を使えるかを、実装前に `VideoEncoder.isConfigSupported` で確かめる。ハードウェア符号化の有無は、WebCodecs では直接分からないため、判定の方法を決める（設計書 23.7 章）。
- **同じ画面の判定（F-037）**: 縮小後の画像を画素単位で比べる。比べる方法（ハッシュの種類）と、その計算時間を実装時に計測する。
- **スキップフレームの作り方（F-037）**: 直前のフレームを参照するスキップフレームを、符号化器で 1 回だけ作る方式を検証する。mp4 の時刻を伸ばす方式（stts）は、ffprobe の平均フレームレートが 10 にならないため、採らない。
- **スピーカーの音の取得（F-022）**: OS ごとに取得の方法が違う。Linux と Windows で取得できるかを、実装時に確認する。
- **停止時の多重化の時間（F-031）**: 再符号化をしないため短いと見込む。実測で確認する。
- **映像の画質（F-024）**: 1080p・10fps・3Mbps では、720p・1.5Mbps と同程度の画質になると見込む（模擬計測）。実機で確認する。
- **Linux のスピーカーの音（F-022）**: 決定により、音声の符号化は Opus にした（ADR-0026）。Linux では、スピーカーの音（システム音）の取得方法が未決。この環境には PulseAudio の monitor 入力があり、候補になる。実装していない。現状はマイクの音だけを録音する。
- **Linux で録画ウィンドウが映る（F-027、確認済み）**: 表示保護（`setContentProtection`）は Linux では効かない。候補: 録画中だけ窓を最小化する、窓を画面の外へ移す。どちらも、録画中の経過時間の表示に影響する。
- **繰り返しフレームの一致（F-037）**: 実機の確認で、繰り返しのフレームは完全には一致しなかった（小さな差が一部の画素に出る）。画面の小さな変化（点滅するカーソル、時計など）か、スキップフレームの残差かは未確認。残差なら、繰り返すうちに画面がずれるおそれがある。その場合の代替案は、サンプルの長さを伸ばす方式（ADR-0020 の代替案）。
- **ビットレートの制御（F-024）**: この環境のソフトウェア符号化（OpenH264）は、フレームスキップを有効にしないと、ビットレートを制御しない（警告が出る）。3Mbps の目標を守れない場合がある。
- **出力の色域（F-024）**: 出力の画素形式は `yuvj420p`（フルレンジ）。一部のプレーヤーで色が変わるおそれがあるため、必要なら `yuv420p` に変換する。
- **未検証の経路**: 2 時間の自動停止（F-029）、空き容量の不足による停止（F-035）、異常終了（F-040）、ハードウェア符号化（F-036。この環境には無い）、Windows の動作（スピーカーの音を含む）。
- **Windows の確認（4.2）**
- **次回起動時の掃除（F-039、F-040）**: 決定。空き容量の不足で止めた録画と、異常終了の録画は、mp4 にならず、見られない（システムの安定性を優先）。
- **途中の mp4（F-031、F-040）**: 決定。途中で失敗・異常終了した mp4（`.partial`）は削除する。

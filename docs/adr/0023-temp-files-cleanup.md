# ADR-0023: 一時ファイル、途中の mp4、起動時の掃除の方針

- **Status**: Accepted
- **Date**: 2026-11-21

## Context

録画は、一時ファイル（中間データ）を作りながら進む。途中で止まったり、失敗したりすると、一時ファイルや途中の mp4 が残る。
それらを、どのように扱うかを決める必要があった。

## Decision

- 録画ごとに一時フォルダ `recording-<開始時刻>/` を作り、`state.json` に状態を書く。状態は `recording`、`stopping`、`stopped-space`、`saved` の 4 つ（[設計書 26 章](../design.md#26-一時ファイルの掃除と異常終了)）。
- 書き込み中の mp4 は `screen_<時刻>.mp4.partial` の名前にする。完了したら `.mp4` に変える（F-031）。
- 多重化が途中で失敗したときは、`.partial` を削除する。中間ファイルは残す（決定）。
- 異常終了（クラッシュ、電源断）のときは、次回起動時に中間ファイルと `.partial` を削除する（F-040、決定）。
- 空き容量の不足で止めた録画は、次回起動時に掃除する（F-039、決定）。
- 保存が完了した録画の一時ファイルは、すぐに削除する（F-030）。
- `state.json` が読めないフォルダは、削除せずログに残す（誤って消さないため）。
- 掃除は起動後に非同期で行う。失敗してもアプリは起動する。

## Consequences

- 異常終了や空き容量の不足で止まった録画は、見られない。利用者には、その仕様を画面と README で説明する。
- `state.json` は、状態が変わるたびに書き換える。書き換えは一時ファイルに書いてから置き換え、書きかけで壊れないようにする。
- 途中で失敗・終了した `.partial` のパスは、`state.json` の `partialPath` に記録する。起動時の掃除で、そのパスを消す。

# ADR-0018: 中間形式は H.264 を録画中に符号化し、3 分単位の一時ファイルに保存する

- **Status**: Accepted
- **Date**: 2026-11-21

## Context

録画は 2 時間まで続く。映像をそのまま保存するとサイズもメモリも足りないため、録画中は圧縮した中間データを一時ファイルに書く必要がある。
検討した中間形式は次のとおり（720p、10fps、2 時間の見積もり）。

| 方式 | 2 時間の中間データ | 停止時の処理 | 判定 |
|---|---|---|---|
| 未圧縮（I420） | 約 100GB | 多重化 | 採らない（保存もメモリも不可） |
| JPEG（1 枚 100〜200KB と仮定） | 約 7〜14GB | 復号して H.264 に符号化（長時間） | 採らない |
| WebM（VP8/VP9） | 約 1.8〜2.7GB | 復号して H.264 に符号化（画質が 2 回劣化） | 採らない |
| H.264（録画中に符号化） | 約 1.0GB | 多重化のみ（再符号化なし） | 採用 |

## Decision

- 録画中、映像は H.264 に符号化する（[ADR-0016](0016-screen-video-format.md)、[ADR-0019](0019-encoder-hw-first.md)）。
- 符号化したサンプルは、**3 分（1800 フレーム）ごと**の一時ファイルに書き出す。各一時ファイルの先頭がキーフレームになるとは限らない（繰り返しフレームの省略のため）。多重化は先頭から順に読むので、再生の開始点は問題にならない。
- 一時ファイルは、時刻・種類・長さを付けたサンプルを順に並べた、アプリ独自のコンテナにする。フレームごとのファイルは作らない。
- 停止時は、一時ファイルのサンプルを mp4 に多重化する（再符号化しない）。
- 録画時間は 2 時間が上限。上限に達したら自動で停止して保存する（F-029）。

## Consequences

- 中間データと mp4 は、どちらも約 1GB になる。停止時のピークは約 2GB。
- 録画中は CPU を使う（[ADR-0019](0019-encoder-hw-first.md)）。停止は多重化だけなので速い。
- 独自のコンテナの書き込みと読み込みを実装し、テストする必要がある。
- 一時ファイルは mp4 として直接は開けない。見られるのは、停止時に mp4 の作成が成功したときだけになる（[ADR-0022](0022-disk-space-stability.md)）。

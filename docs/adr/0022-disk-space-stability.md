# ADR-0022: 空き容量を監視し、不足時は安定性を優先して mp4 を作らずに止める

- **Status**: Accepted
- **Date**: 2026-11-21

## Context

中間データと mp4 を合わせて、2 時間で約 2GB が必要になる。録画中に空き容量が尽きると、録画データが壊れたり、システム全体が不安定になったりするおそれがある。
空き容量が足りないときに、無理に mp4 を作るか、録画を止めるかを決める必要があった。

## Decision

- **録画の開始前**: 空き容量が 6GB 以上あることを確認する（仮。ADR-0027 で 3GB から変更）。足りなければ録画を始めない（F-035）。
- **録画中**: 10 秒ごとに空き容量を確認する（`fs.promises.statfs`）。空き容量が「現在の中間データの大きさ＋0.5GB」を下回ったら、録画を止める（F-035）。
- **空き容量不足で止めるとき**: mp4 は作らない。ディスクへの追加の書き込みを行わず、システムの安定性を優先する（決定）。中間ファイルの場所を画面に表示し、状態を `stopped-space` にする。
- **通常の停止**: 空き容量が「中間データの大きさ＋0.2GB」以上あるときだけ mp4 を作る（仮）。足りなければ mp4 を作らず、中間ファイルを残す。
- 録画が見られるのは、mp4 の作成（多重化）が成功したときだけ（決定）。

## Consequences

- 空き容量不足で止めた録画は、見られない。次回起動時に掃除で消える（[ADR-0023](0023-temp-files-cleanup.md)）。
- 安定性を優先するため、録画を失うことを利用者に説明する必要がある。画面には、録画が止まった理由と中間ファイルの場所を表示する。
- 数値（6GB、0.5GB、0.2GB）は仮の値。実機で測って決め直す。

# ADR-0019: 符号化はハードウェアを優先し、使えないときは録画中に CPU で行う

- **Status**: Proposed（ハードウェアの判定方法を、Electron 45 の Linux と Windows で確かめる）
- **Date**: 2026-11-21

## Context

録画中の H.264 符号化は、CPU への負荷が大きい。CPU 使用率は 10% 以下にしたい（7.3a）。ハードウェア符号化が使えれば、この負荷を下げられる。
WebCodecs の `VideoEncoder` は、`hardwareAcceleration` で希望を指定できる。ただし、実際にハードウェアが使われたかどうかは、直接は返さない。

## Decision

- `VideoEncoder` を `hardwareAcceleration: 'prefer-hardware'` で作る。
- ハードウェア符号化が使えないとき（指定が無視されたとき、対応しない環境のとき）は、CPU（ソフトウェア符号化）で録画中に符号化する。
- 使った方式（ハードウェアかソフトウェアか）を、録画ごとに記録する。
- CPU 使用率が上限を超えそうなときは、フレームレートを下げる（F-023 の例外）。停止時の多重化には、この上限を当てない（7.3a）。

## Consequences

- ハードウェアの判定方法が決まるまで、この ADR は Proposed のままにする。候補は、エンコーダーの応答の確認と、短い試験符号化の速さで判定する方法。
- ソフトウェア符号化では、フレームレートが 10fps より下がることがある。利用者には、それを記録で示す。
- Chromium の Linux ビルドで H.264 が使えないときは、ffmpeg などの同梱が必要になる。配布サイズとライセンスに影響するため、その判断は別の ADR にする。

## 実装での確認（2026-11-21）

- この環境では、`prefer-hardware` の設定は `isConfigSupported` で使えないと返された。そのため、ソフトウェア符号化（OpenH264）が使われた。
- 使われた方式は、録画ごとに記録する（実装の方式）。ハードウェアが実際に使われたかどうかは、この環境では確認できていない。
- ハードウェア符号化の経路は、この環境では確認していない。Windows で確認する。

# ADR-0021: 録画対象はプライマリ画面とし、画面 ID で扱う

- **Status**: Accepted（窓の除外は Linux で別途確認する。[設計書 23.3 章](../design.md#23-画面録画のパイプライン)）
- **Date**: 2026-11-21

## Context

全画面を録画する。複数のディスプレイがあるときに、どれを録るかを決める必要がある。将来は画面を選べるようにする予定がある。
また、録画中はアプリ自身の窓（256×80）が画面に出ているため、映像に映り込まないようにする必要がある（F-027）。

## Decision

- 録画の対象は、プライマリ画面（全画面）1 つにする（F-028）。プライマリ画面の ID に一致する画面がないときは、一覧の先頭の画面を使う（実装の動作）。
- 内部では、画面を画面 ID（`displayId`）で扱う。今は、プライマリ画面の ID を固定値で指定する。将来、画面を選ぶ機能は、この ID を変えるだけで対応する。
- 画面の取得は、メインプロセスの `session.setDisplayMediaRequestHandler` で行う。ピッカーは出さず、`displayId` の画面を返す（[ADR-0025](0025-screen-capture-permission.md)）。
- 録画中、アプリの窓は画面に表示したままにする（経過時間を見せるため）。映像からは除外する。
  - Windows と macOS: `BrowserWindow.setContentProtection(true)` を使う。
  - Linux: 方法が限られる。候補は、録画中だけ窓を画面外へ移すこと。実装時に確認する。

## Consequences

- 複数画面の環境では、通常はプライマリ画面が録画される。プライマリ画面が一覧にないときは、別の画面が録画されることがある。利用者が別の画面を選ぶ機能は、将来の機能まで待つ必要がある。
- Linux で窓を除外できない場合、映像にアプリの窓が映る。その場合は F-027 の受け入れ条件を満たさないため、実装前に決め直す。

## 実装での確認（2026-11-21）

- 表示保護は、この Linux 環境では効かない。窓は映像に映った（確認済み）。
- 画面の取得（ピッカーなし、プライマリ画面）は、この環境で動いた。

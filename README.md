# jsVodeoRecoder   音声・画面レコーダー

AIによるコード生成の学習
Electron と React で作った、小さなデスクトップ向けの録画アプリです。全画面（プライマリ画面）の映像を mp4 に録画します。

- 映像: H.264、1920×1080、10fps（固定）、約 3Mbps（可変）
- 音声: Opus、48kHz、モノラル、128kbps（マイクとスピーカーの音を混ぜる。下の「既知の制限」を参照）
- 操作: ● 開始、❚❚ 一時停止、▶ 再開、■ 停止。録画中は音量バーと dB 表示を見られる
- 保存先: Downloads フォルダ（保存先のダイアログは出ない）
- 上限: 2 時間で自動停止し、ここまでの分を保存する
- 画面: 256×80 の固定サイズの小さな窓

要件は [docs/requirements.md](docs/requirements.md)、設計の概要は [docs/screen-recording-design.md](docs/screen-recording-design.md)、詳細は [docs/design.md](docs/design.md) の 23〜26 章、設計判断は [docs/adr/README.md](docs/adr/README.md) にあります。機能の一覧と検証状況は [docs/features.json](docs/features.json) にあります。

## 必要な環境

- Node.js 22.12 以上（推奨。Electron 45 と依存パッケージの要件）
- npm
- マイク（録画に必須）
- 画面収録の権限（OS の設定で、アプリに画面の収録を許可する。下の「権限」を参照）
- 検証用に ffprobe（録画した mp4 の確認に使う。アプリ本体には含まれない）

対象 OS は Linux と Windows です。macOS は将来対応の予定です（画面収録の許可と説明文が必要）。検証は Linux でのみ行いました。

## セットアップ

```bash
npm install
```

## 起動

ビルドしてから Electron を起動します。

```bash
npm run start
```

画面だけをブラウザで確認するには、Vite の開発サーバーを使います。ただし、録画は Electron でしか動きません。

```bash
npm run dev
```

## 使い方

1. 起動すると、マイクの許可を一度求められます。許可すると、マイク名が一覧に表示されます。
2. 左下のプルダウンから、使いたいマイクを選びます（録画中は変えられません）。
3. **●（開始）** を押すと録画が始まります。経過時間と音量バーが動きます。
4. **❚❚（一時停止）** と **▶（再開）** で、一時停止と再開ができます。一時停止中の時間は録画に含まれません。
5. **■（停止）** を押すと録画が終わり、mp4 が Downloads フォルダに保存されます。保存中は「保存しています… NN%」と進み具合が出ます。保存が終わると、保存先の絶対パスが表示されます。

ファイル名は `screen_YYYYMMDD_HHMMSS.mp4` で、録画を開始した時刻です。

### 録画できない場合・録画が残らない場合

| 状況 | 動作 |
|---|---|
| 空き容量が 6GB 未満 | 録画を始めません（仮の値） |
| 録画中に空き容量が不足 | 録画を止めます。mp4 は作りません。中間ファイルの場所を表示します。この録画は見られません |
| 停止時の空き容量が足りない | mp4 は作りません。中間ファイルの場所を表示します |
| mp4 の作成が途中で失敗 | 途中まで書いた mp4 を削除します。中間ファイルは次回起動時に削除します |
| 録画中にアプリが終了（クラッシュ、電源断） | 中間ファイルは次回起動時に削除します。この録画は見られません |

録画を見られるのは、停止時に mp4 の作成が成功したときだけです。

## 権限

- **マイク**: 録音に必要です。
- **画面収録**: 画面を録画するために必要です。Windows は専用の許可が要りません。Linux は、環境によって OS の許可が出ることがあります。
- アプリは、マイクと画面収録以外の権限を許可しません。

## 既知の制限

- **Linux ではスピーカーの音が入りません（F-022）**: マイクの音だけを録音します。スピーカーの音を取る方法（PulseAudio の monitor など）は未決です。
- **Linux では録画ウィンドウが映ります（F-027）**: 表示保護は Linux で効きません。映らないようにする方法は未決です。
- **ビットレートが目標どおりにならないことがあります（F-024）**: ソフトウェア符号化（OpenH264）は、フレームスキップを有効にしないと、ビットレートを制御しません。
- **繰り返しフレームが完全には一致しないことがあります（F-037）**: 原因（画面の小さな変化か、スキップフレームの残差か）は未確認です。
- **ハードウェア符号化は、この環境では使えませんでした（F-036）**: CPU（ソフトウェア符号化）で録画します。ハードウェアの判定方法は未決です。
- **空き容量の数値は仮の値です（F-035）**: 実機で測って決め直します。
- 録画を見られるのは、停止時に mp4 の作成が成功したときだけです（上の表を参照）。
- 再生機能、保存先の選択、画面の選択（プライマリ画面だけ）、fps の変更（既定の 10fps だけ）は、まだありません。

## 開発

### テスト

静的な検査（ソースの記述と設定値の確認）と、録画処理の単体テスト（Node.js の `node:test`）を実行します。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -m "not build"
```

すべてのテスト（`npm run build` を含む）は、次のように実行します。

```bash
.venv/bin/python -m pytest
```

録画処理の単体テストだけを、直接実行することもできます。

```bash
node --test electron/recording/
```

実際の録画（Electron を起動して操作し、mp4 を `ffprobe` で確認する）は、[設計書 20 章](docs/design.md#20-再現手順) の手順で行います。

```
.
├── electron/
│   ├── main.cjs            メインプロセス（窓、権限、画面の取得、録画の開始・停止、保存、掃除）

│   └── recording/

│       ├── policy.cjs      空き容量の判定

│       ├── cleanup.cjs     起動時の掃除
│       └── recording.test.cjs  単体テスト
├── src/
│   ├── main.jsx            React の起動
│   ├── App.jsx             UI（経過時間、音量、マイク選択、ボタン、メッセージ）
│   ├── App.css             スタイル（ライト・ダークテーマ対応）
│   └── recorder.js         画面の取得、10fps、同じフレームの判定、符号化、音声の混合
├── docs/
│   ├── requirements.md     要件定義書
│   ├── design.md           設計書（詳細）
│   ├── screen-recording-design.md  画面録画の設計書（概要）
│   ├── adr/                設計判断の記録（ADR）
│   └── features.json       機能一覧と検証状況
├── tests/                  pytest（静的な検査と単体テストの実行）
├── index.html
├── vite.config.js
└── package.json
```
